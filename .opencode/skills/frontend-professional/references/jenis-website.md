# Playbook menurut jenis website

Pilih berdasarkan tugas utama. Jangan menerapkan susunan landing page ke setiap produk.

| Jenis | Isi utama | Interaksi dan kondisi penting |
| --- | --- | --- |
| Portofolio kreatif | Karya terkurasi, identitas, proses, kontak | Detail karya, media, keyboard, hak penggunaan |
| Portofolio programmer | Masalah, peran, keputusan, hasil, repo/demo | Studi kasus, status proyek, bukti valid |
| Bisnis/company profile | Layanan, segmen, proses, lokasi, jam, kontak | Penawaran, form error, kanal kontak nyata |
| Landing kampanye | Satu penawaran, target, bukti, CTA | Tracking seperlunya, syarat, hasil submit nyata |
| Dashboard penjualan | Periode, ringkasan, tren, transaksi | Filter, drill-down, ekspor, stale/empty/error |
| Admin internal | Pekerjaan, status, detail, riwayat | Izin, bulk action, destructive confirm |
| Toko online | Produk, varian, stok, harga, pengiriman | Cart, qty, diskon, gagal bayar, stok berubah |
| SaaS | Pengenalan produk dan aplikasi | Onboarding, auth, billing, batas paket, settings |
| Blog/majalah | Arsip, artikel, penulis, tanggal, kategori | Pencarian, pagination, navigasi baca |
| Dokumentasi | Topik, versi, contoh, pencarian | Deep link, code copy, 404, status versi |
| Booking/event | Jadwal, durasi, lokasi, ketersediaan | Timezone, slot berubah, retry, konfirmasi |
| Kursus | Tujuan, kurikulum, pengajar, progres | Resume, akses materi, error jaringan |
| Direktori/listing | Kriteria, lokasi/kategori, detail | Filter URL, hasil nol, peta alternatif |
| Layanan publik/form | Syarat, langkah, dokumen, bantuan | Error summary, review jawaban, simpan jika ada |

## Portofolio

Mulai dari nama/peran dan karya sesuai target, bukan slogan raksasa tanpa bukti. Kurasi karya. Studi kasus menjelaskan konteks, tanggung jawab pribadi, constraint, pendekatan, dan hasil. Pisahkan kerja tim dari kontribusi pemilik. Jika dampak belum diukur, jelaskan secara kualitatif tanpa angka buatan.

Repo, demo dan kontak harus benar. Jelaskan proyek privat. Hindari skill bar persentase tanpa dasar dan logo klien tanpa izin. Portofolio visual mengutamakan media/caption; portofolio engineer mengutamakan keputusan dan hasil yang dipahami pembaca.

## Bisnis dan landing page

Jawab apa, untuk siapa, di mana, bagaimana, berapa/cara estimasi, lalu apa. Susun CTA mengikuti niat pengunjung. Untuk jasa lokal, lokasi/jam dan kontak bisa lebih berguna dari tujuh section fitur.

Tampilkan FAQ dengan pertanyaan nyata. Gunakan foto produk/tim/lokasi yang relevan dan sah. Harga menjelaskan satuan, cakupan dan biaya tambahan bila diketahui. Jika belum ada harga, pakai permintaan estimasi.

Form perlu integrasi nyata, label, validasi, status submit, anti-spam yang sesuai, dan penjelasan data. Demo tidak boleh mengatakan pesan sudah dikirim ke pemilik bisnis.

## Dashboard dan admin

Baca dashboard-dan-data.md. Mulai dari tugas pengguna dan definisi metrik, bukan empat kotak angka acak. Bedakan analisis tren dengan antrean pekerjaan. Daftar transaksi bermasalah bisa lebih penting daripada grafik dekoratif.

## E-commerce

Sampaikan varian, stock, harga dan pengiriman dekat aksi membeli. Total dan stok transaksi diverifikasi backend. Tangani cart kosong, qty invalid, out-of-stock, sesi habis, diskon ditolak, pembayaran pending/gagal.

Jangan menyimpan data kartu sendiri atau membuat sukses pembayaran dari state lokal. Gunakan provider proyek dan verifikasi server sesuai kontrak. Badge, ulasan, diskon dan hitung mundur harus faktual.

## Konten, docs, booking dan aplikasi lain

Situs konten mengutamakan heading, type baca, metadata, navigasi dan pencarian. Docs membutuhkan versi serta contoh sesuai API. Booking memerlukan timezone, perubahan slot dan sumber ketersediaan. Gunakan playbook sebagai pertanyaan produk, bukan resep visual seragam.
